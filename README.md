# sw-cs

> 把客户的一句话，变成「能直接发出去的回复」+「哪句不能说」。
>
> 一个给**女装/服饰类私域客服**用的应答技能（Skill）。装上后你说「客户说：×××」，它回四段：场景定位 / 建议回复 / 必须核实 / 不能说，外加一句「为什么这么说」。

---

## 它解决什么问题

一线客服最常见的问题不是「不知道规则」，而是三个：

| 问题 | 典型表现 | sw-cs 怎么做 |
|---|---|---|
| 客户问「能不能」，客服答「规则怎么写的」 | 客户问 5 次才得到一句「可以」 | **铁律 2**：第一次问就要给是/否/查了才答 |
| 条件分三次给 | 先说发订单号，再说要绑会员，再说要推荐好友——三次往返 | **三件事一次说完** |
| 只会说「我核实一下」然后就消失 | 客户流失，且不知道在等什么 | **铁律 3**：给查什么 + 谁在查 + 什么时候答 |

它不替你决定「能不能赔」，只帮你把话说对——**不能答的部分说清楚什么时候能答，能答的部分当场给。**

## 安装

技能目录（WorkBuddy 用户级）：

```
~/.workbuddy/skills/sw-cs/
```

**三步**：

1. 把 `sw-cs` 整个文件夹放进 `~/.workbuddy/skills/`（Windows：`%USERPROFILE%\.workbuddy\skills\`）
2. 确认路径是 `skills/sw-cs/SKILL.md`，**不是** `skills/sw-cs/sw-cs/SKILL.md`
3. 完全退出再打开应用（技能在启动时加载）

**验证**：发一句 `客户说：领了券没减上，我后天要穿`，应返回四段结构。如果它反问你「哪家店铺」，说明没读到技能，检查目录层级。

> 想一句口令安装，需要发布到 WorkBuddy 内置推荐市场；本仓库只提供源码与打包目录。

## 换成你自己的口径

`references/01-口径卡.md`、`02-场景路由.md`、`03-话术库.md` **是生成文件，不要手改**。改了下次重生成会被覆盖。

正确做法：

1. 准备一份 SOP 工作簿（结构见 `scripts/refresh.py` 顶部字段说明）
2. 跑一次：

```bash
pip install openpyxl
python3 scripts/refresh.py /path/to/your-sop.xlsx
```

3. 三份文件自动重写。

**为什么要有这个脚本**：276 个字段手抄必然漂移。口径只在工作簿里改一处，重跑一次，全部同步。

## 设计原则

1. **不产生事实。** 价格、库存、时效、名额、券规则、赔付标准——不知道就写 `【待核实】`，不猜。
2. **能/不能，第一句说清。** 不许先讲动作、先讲背景。
3. **不确定可以说，但不能只说不确定。** 必须同时给：查什么、谁在查、什么时候答复。
4. **先接情绪，再讲道理。** 客户说「起球了质量太差」，回「这是羊毛正常现象」等于宣战。
5. **不越权。** 赔付、破例、补发由人定；模型只负责说清楚、说得体。

---

## 边界（重要）

- **无系统对接。** 订单状态、库存、券是否生效、会员等级，全部需要人工在后台查。它不知道，只会标 `【待核实】`。
- **不决定能不能答应。** 遇到超出授权的（超封顶赔付、特殊品类退换、监管投诉），一律升级。
- **口径是示例，不是制度。** 本仓库里的金额、天数、门槛用于说明结构，**上线前必须替换为本公司现行规定**。

## 数据与合规

- 仓库内不含任何客户姓名、电话、地址、订单号。
- 文中引用的话术片段为整理后的通用对话样式，用于说明句式优劣。
- 使用前请确认所在公司对客服话术、赔付权限的对外披露要求。
